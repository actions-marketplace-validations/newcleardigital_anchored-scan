# Anchored Scan

A free GitHub Action that comments on every pull request with two things AI-written code gets wrong and reviewers miss:

1. **A fixed number used in logic in more than one file.** A fee, a limit, a rate typed into a second place. The next change moves one copy and not the other.
2. **A generated file edited by hand.** The edit is lost the next time the generator runs, and until then the file no longer says what its source says.

No configuration. No account. Nothing leaves your runner: the scan reads your checkout and talks only to the GitHub API, to list the pull request's files and to write its comment.

[![checked by Anchored](https://img.shields.io/badge/checked%20by-Anchored-2F5E8C)](https://anchored.newcleardigital.com/?ref=badge)

## Use it

`.github/workflows/anchored.yml`:

```yaml
name: Anchored Scan
on: pull_request
permissions:
  contents: read
  pull-requests: write
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: newcleardigital/anchored-scan@v1
```

That is all. The first pull request gets one comment, and every new push updates the same comment instead of adding another.

## What the comment looks like

> ### Anchored Scan
> **2 possible copied fixed values · 1 generated file edited in this PR** · zero-config, advisory
>
> | Value | Files | Where |
> |---|---|---|
> | `0.015` | 2 | `api/quote.py:2` ✱, `app/fees.py:3` |
> | `5000` | 2 | `api/quote.py:3` ✱, `app/fees.py:2` |
>
> - `app/gen.py` — its header says it is generated

✱ marks files changed in the pull request.

## From advice to rules

Without configuration the scan only advises: it never fails your build. Add `anchor-core.json` at the repository root and it runs the four [Anchored Lite](https://github.com/newcleardigital/anchored-lite) checks instead, and fails the build when one breaks:

```json
{
  "constants": "fees/limits.py",
  "watch_numbers": [1.5, 0.25, 5000],
  "banned_words": { "customer": "say cardholder, the team agreed on it" },
  "generated": [{ "file": "docs/LIMITS.md", "command": "python3 tools/gen_limits.py" }],
  "decisions": "docs/decisions"
}
```

| Check | Fails when |
|---|---|
| fixed numbers in one place | a watched number is used in logic outside the constants file |
| agreed vocabulary | a name contains a word the team agreed not to use |
| generated files in sync | running the generator changes the committed file |
| decisions written down | a decision file has no real `## Decision` section |

They are the same checks, byte for byte, that Anchored Lite runs inside Claude Code the moment the agent saves a file, so the agent fixes the break in the same turn and the pull request arrives clean.

A line that is a deliberate exception carries `core-allow: <why>`.

## Inputs

| Input | Default | Meaning |
|---|---|---|
| `path` | `.` | Folder to scan |
| `fail-on` | `auto` | `auto`: fail only when a check from `anchor-core.json` fails · `never`: report only · `findings`: fail on any finding |
| `comment` | `true` | Post and keep updating one pull request comment |
| `token` | `github.token` | Token used to list the pull request's files and to comment |

Outputs: `mode` (`zero` or `checks`), `copies`, `generated-edits`, `failed`.

Pull requests from forks get a read-only token, so there the report goes to the job summary instead of a comment.

## How it decides

- **Copied fixed values.** A number counts as used in logic when it stands beside a comparison, or multiplies or divides. It is reported when that happens in two or more files outside tests, vendored code, mocks and bundles. Units, sizes, bit masks, HTTP status codes and small whole numbers are skipped, because in an unknown codebase they are mostly indexes and counts. Rates and odd amounts are listed first. It is a pattern match, not understanding: it finds candidates for a human to judge.
- **Generated files.** A changed file whose first lines say it is generated (`DO NOT EDIT`, `@generated`, `generated by`), or that `anchor-core.json` lists as generated.

## When the rules come from outside

If your code follows a rulebook someone else wrote, such as card-scheme rules, regulator fees, pricing law or a contract, an auditor will ask you to show that each rule became code, was tested and was approved by a named person. That is what [Anchored](https://anchored.newcleardigital.com/?ref=scan-readme) adds.
